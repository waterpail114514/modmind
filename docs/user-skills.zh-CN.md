# 用户 Skills

工作台的「更多操作 → Skills」管理用户提供的工作流；简洁模式使用输入框下方的 Skills 图标。支持新建和编辑 `SKILL.md`、导入单个文件或完整目录、搜索、启停及移除。用户 Skills 对所有项目可用，变更在下一次发送时生效，正在运行的任务保留本轮副本。

## 格式与选型

沿用 [Agent Skills](https://github.com/agentskills/agentskills) 的 `SKILL.md` 格式及渐进读取方式。上游规范采用 Apache-2.0 许可证；本次没有复制其实现代码，也没有新增依赖。复用仓库已有的 `yaml` 2.8.x 解析库、Node 文件 API、工作台对话框及 MCP 桥接。无需引入依赖 Python 的上游验证工具；本地元数据校验与受限文件复制足以完成这项任务，首次断网也可使用。

```markdown
---
name: my-workflow
description: 需要整理模组发布材料时使用。
---

按用户本次要求检查发布材料并列出缺少项。
```

名称使用 1–64 位小写字母、数字及单连字符，不能与内置 Skill 重名；description 为 1–1024 字符，正文不能为空。其余 YAML 字段会保留。编辑 `SKILL.md` 不改动已导入的配套资源；需要修改资源时，可在原始目录修改，再移除旧副本并重新导入。

## 存储与边界

- 用户选择目录时复制其中的文件和子目录，包括 references、scripts 和 assets；选择单个 `SKILL.md` 时只复制该文件。导入不会执行脚本，也不会修改原始文件。
- `SKILL.md` 上限 256 KiB，目录上限 1000 项、64 MiB；拒绝符号链接、特殊文件、重复名称与路径越界。正文编辑采用版本校验，避免多个窗口静默覆盖。
- 存储在应用用户数据下的 `workbench-skills`，不写入用户全局 Codex 配置。每轮启用项复制到当前项目的运行目录 `user-skills`，与内置 Skill 分开。
- 主机注入名称、用途、版本和精确路径，不预读全部正文。工作台按需调用只读 `modmind_user_skills` 的 list/read 操作，读取本轮启用项或不超过 256 KiB 的文本参考文件。AI 不通过这个工具安装、停用或删除 Skill。
- Skill 不改变工作台审批、项目边界或制作功能选择；灵感台不加载用户 Skills。尚不提供远程仓库、压缩包导入、自动依赖安装或脚本运行环境。

## 验证

存储测试覆盖离线创建、导入、资源保留、启停、重载、移除、重复名称、并发版本冲突、YAML 错误、容量限制和路径限制。MCP 测试通过实际 stdio 工具目录及调用链读取正文和参考文件，检查项目切换、运行中修改的副本隔离、停用项与只读模式。
