# 应用更新日志

内容统一维护在 `src/shared/appChangelog.ts`，随应用打包，读取和展示不联网。

可以先在 `APP_CHANGELOG` 顶部维护下一版本草稿，按「新增 / 改进 / 修复 / 调整」等分组填写实际变更；高于当前应用版本的条目不会显示。正式发版时再同步 `package.json` 版本，并确认有同版本条目。保留历史条目，默认折叠。`appChangelogService.test.ts` 会检查当前版本条目、版本顺序和重复项；不要把下一版未发布内容挂在上一版名下。1.4.12 的条目取自 [GitHub 发布记录](https://github.com/waterpail114514/modmind/releases/tag/1.4.12)。

1.4.14 草稿按当前工作区相对 `34bdbbd` 的 Git diff 整理，也核对了尚未跟踪的新源码。内容依据包括本机 Codex 配置与工作台接入、项目导入状态及限制、快照存储、Forge 安装恢复、下载状态和更新日志功能。当前 `package.json` 保持 1.4.13；此草稿不代表 1.4.14 已发布，也不代表本次重新验收了全部功能。

## 展示规则

- 全新用户首次启动只建立版本基线，不弹窗。设置 → 关于 → 版本与更新 → 更新日志可手动查看。
- 高于此前已运行的最高版本，且内置当前版本日志时，在主窗口准备好后展示一次；实际显示后持久化已展示状态。启动中断、尚未显示时，下次可继续显示。
- 相同版本重启、重装、降级以及降级后回到已经看过的版本不再弹窗。跨版本升级直接显示本次版本，可展开历史。
- 开发环境不读写启动记录、不自动弹出。分离窗口不领取自动展示状态。
- 启动记录位于用户数据目录的 `app-changelog-state.json`。损坏或无法写入时安静降级，主界面和手动查看仍可使用。

## 旧版本迁移

Windows NSIS 安装器在卸载旧版前读取其 `DisplayVersion`，安装成功时将本次版本、前一版本写入安装目录的 `resources/modmind-install-versions.txt`。主进程仅在用户启动记录不存在、安装标记匹配当前版本时采用它；直接下载安装包覆盖旧版也属于升级。全新安装写入空的前一版本，不根据缓存、项目或设置文件猜测升级。

macOS / Linux 此前没有安装器版本标记，首次引入该功能时只能建立基线；之后的升级按用户版本记录正常触发。清空用户数据会丢失已展示记录；Windows 若仍保留升级安装标记，可能重新展示一次。

## 实现选择与验证

复用现有 `appUpdatePolicy` 语义版本比较、Electron IPC、React 弹窗与主题变量，以及 electron-builder 25.1.8 的 NSIS 升级钩子与注册表信息（[上游](https://github.com/electron-userland/electron-builder)，MIT）。没有新增依赖、在线服务或 Markdown 渲染器；这里是简短本地状态逻辑，无需引入更新日志 SaaS/SDK。弹窗属于应用界面展示，不新增工作台 MCP 工具。

回归覆盖全新安装、升级一次、展示前中断、覆盖安装迁移、同版重装、降级、跳版、异常记录、开发环境；界面检查手动入口、历史展开、键盘焦点、关闭、深浅主题和窄窗口。

本次验证：更新逻辑及设置检索共 64 项测试通过；类型检查、主题检查和生产构建通过。`node scripts/app-changelog-smoke.mjs` 使用独立用户目录、真实主进程 / preload / 渲染页面，模拟已打包版本，验证全新安装、升级、重启、Windows 旧版标记、手动查看、焦点恢复、深浅主题及 390 px 窄窗口。NSIS 使用微型占位应用成功编译了实际安装器脚本；没有在真实用户安装上执行覆盖安装，也没有生成可发布的新安装包。macOS / Linux 尚未进行实机验证。
