# 数据包与共用游戏资源

2026-11-01，当前 main / 2.0.0-preview.1 工作树实施。用户确认名称为「数据包」，替代原「内容与数据」中的游戏数据编辑；采集能力融入使用位置。未发布官方目录或修改用户安装版。

## 用户流程

- 安装「数据包」功能。模组项目直接编辑 `src/main/resources/data/`；整合包项目可新建数据包、导入 ZIP，或打开 datapacks、OpenLoader、Paxi、KubeJS 位置的已有内容。
- 左侧搜索、分页选择数据文件。有序/无序配方使用九宫格和物品选择器；标签与简单掉落使用表单。进度、条件、函数、复杂掉落及自定义 JSON 使用源码；已有未知字段保留。
- 「图形 / 源码 / 改动」共用当前草稿。保存时验证内容和原文件 SHA-256；外部改动时保留草稿，允许另存，不覆盖其他操作的新版本。切走再返回保留当前进程内草稿，缓存最多 4 个项目；未承诺强制退出后恢复未保存草稿。
- 删除前二次确认，修改/删除前保留恢复副本。数据包更多菜单中的「恢复历史」可回写旧版本；恢复同样检查当前文件版本。历史最多 50 份、合计 32 MiB，按项目保存。
- ZIP 可只读浏览并「解包编辑」，原件保留；导入写入新目录。导出生成项目 `build/data-packs/` 中含 `pack.mcmeta` 和 `data/` 的 ZIP。进入游戏测试只打开既有测试流程，**不意味着已部署到世界或已验证生效**。
- 原「内容与数据」的语言文本、资源 JSON 保留在资源包的「语言与资源定义」子页；旧后台生成接口保留兼容。

## 资源来源

`mc-pull` 改名「本地游戏资源」，取消独立导航与原采集页面的打包，成为依赖自动安装的支持组件。原功能 ID、项目 `.modmind/mc-capture/`、活动包和已有采集格式保留。

建筑预览的「方块资源」、数据包物品选择器的「资源来源」和数据包更多菜单共用来源管理：选择实例、切换、刷新、导出采集包、清理采集结果，以及导入已有探针产物。已有建筑预览的首次选择实例快捷操作保留。来源查询只读当前项目，不再为了打开管理面板扫描系统游戏目录。

新编辑器优先复用内置原版目录，首次断网且没有游戏实例时仍可选择 1.20.1、1.21/1.21.1 基线物品，其他版本可输入 ID 或补充本地资源。采集图标按当前页/当前配方读取，不为显示目录下载游戏。目录解析缓存最多 4 份，30 秒失效；文件大小/mtime/ctime 变化立即失效，失败条目可重试。图标每批最多 64 个，每图 128 KiB、每批 2 MiB；缺图时仍可使用名称和 ID。

静态采集的运行时属性继续标为 unknown，不把近似图标、目录或文件校验当作运行期真实性证明。未附带探针或探针工程，导入现成结果不等于已具备完整游戏内采集。原 FTB 图标/名称服务仍保留；本轮共用的是建筑预览与数据包的采集来源和目录，不宣称已将所有旧资源解析器重写成一个。

## 复用与版本范围

先核对现有 ContentService、文件事务、物品目录、FTB 资源服务、采集/预览格式及功能插件机制；实现复用项目写入边界、变更串行化、ZIP 读取、yazl、内置物品基线和既有采集核心。

上游核对 [Misode](https://github.com/misode/misode.github.io)（MIT，2026-10-29 主分支提交）、[Spyglass](https://github.com/SpyglassMC/Spyglass)（MIT，2026-10-31 主分支提交）与 [Ajv](https://ajv.js.org/guide/managing-schemas.html)。Misode 是 Preact/Vite 整站并组合多个预览版本，Spyglass 是语言服务/类型系统；完整接入超出首批有限类型。本轮复用仓库已安装的 Ajv 8.20.x（MIT）编译有限类型规则，不引入新的 npm 依赖、不打包整站或下载游戏资源。图形表单与旧 JSON 的局部无损转换本地实现；未声称等价于完整 mcdoc/Spyglass 校验。

参考上游 mcmeta 的真实样例处理配方差异：1.20.5 起产物使用 `id`；1.21 起使用单数数据目录；1.21.2 起材料使用字符串/标签引用。保持原有结果组件和未知顶层字段，无法表达的复杂材料改用源码而非扁平化丢弃。

新建独立数据包/模组数据导出元数据目前明确适配 1.20.1、1.20.6、1.21、1.21.1、26.3；未适配版本拒绝猜测格式号，可导入已有正确元数据的数据包继续编辑。26.3 使用 `min_format/max_format [121,0]`。测试夹具覆盖 1.20.1、1.20.6、1.21.1、1.21.2、26.3 的配方转换；这不扩大为全部版本和模组扩展格式支持。

基础校验覆盖 JSON、受支持配方结构/符号、引用格式、数量、标签与简单掉落字段。复杂配方、掉落条件、进度、条件数组、命令及模组自定义类型明确返回校验边界；不完整校验所有引用是否存在，也不模拟执行命令。高级源码保存不丢原始字段。

## 功能包与升级

新增 `data-packs` 1.0.0，已将共用采集核心直接打入自己的功能包，无需安装 `mc-pull`；配套更新为 `modpack-content` 1.6.0、`resource-packs` 1.6.0。模组和整合包推荐组合加入数据包功能。新功能与原整合包数据包沿用 `modpack-datapacks` 视图 ID，原 `modpack-content` 不再声明该入口。

**已有旧版文件清单插件时，先更新 `modpack-content` 再安装 `data-packs`**，避免旧清单仍占用相同视图 ID。发布数据包时配套更新这两个功能。旧导入的 `mc-preview`、`mc-pull` 已按用户要求下架；其源码仍可用于本地开发，发布流程排除这两个 ID。数据包资源来源继续复用同一份采集业务源码与现有项目数据，不依赖旧包的云端下载。采集包仍是 `modmind-capture-pack`，不是 Minecraft Data Pack。

## 工作台 MCP

三个工具经功能包工具发现与调用路由注册；界面直接调用同一动作服务：

| 工具 | 操作与边界 |
| --- | --- |
| `modmind_data_pack_query` | list/files/read/validate/history；文件分页，回读源码、基线及校验范围，恢复记录只在当前项目与数据包中查询 |
| `modmind_data_pack_write` | create-pack/create/save/remove/export/restore；save/restore 必须提供预期基线，新增文件用 null，删除保留恢复副本；只读会话拒绝 |
| `modmind_data_pack_items` | 搜索分页物品目录与当前采集来源，不联网、不启动游戏 |

所有动作都验证输入 schema、工作台/加载器适用范围、当前项目上下文及路径；沿用插件权限授权。数据文件只允许当前数据包 `data/` 中的 JSON/mcfunction，不接受任意项目写入位置。链接/越界、只读、过期 SHA 和保存冲突都拒绝。恢复历史、导出 ZIP 都是实际产物，而非仅返回「请求已接收」。
