# 指定 JAR 的隔离服务端场景

现有服务端测试页的「运维与验证 → 场景验证」增加「隔离测试」选项，不新增页面。普通服务端启动和原有全包场景继续使用原流程。指定 JAR 场景只通过新的独立任务服务运行，不调用可能复用持久实例的 `LocalServerManager.verify()`。

## 输入与运行

- 固定 Minecraft、Loader 与 Loader 版本，输入 1–64 个 JAR。项目外文件需通过文件选择器授权；工作台可查询已选文件，或提交项目内路径。每个输入必须提供 SHA-256，复制后重新校验。
- 复用归档读取和 TOML / JSON 解析，校验模组 ID、必需依赖、Minecraft / Loader / Java 约束，支持内嵌 JAR。重复 ID、重复文件名、缺依赖、哈希变化或无法解释的版本声明会失败，不自动加入整包模组或下载缺少的前置。
- 每个任务在 `.modmind/server/scenarios/<taskId>/game` 创建唯一运行目录，只绑定 `127.0.0.1`，使用离线模式和全新世界。宿主不接收任意输出路径，不复制正式世界、用户配置或启动脚本。
- `restart` 步骤正常停止并重新启动同一隔离世界，以验证持久化；另一任务创建新的世界。单任务最多 40 步，每步日志断言有时限，总时限默认 10 分钟，最高 30 分钟。
- Java、安装器和进程复用现有服务。固定版本运行时独立缓存，最多保留 4 个版本，只复用运行时文件，不复用世界、模组或场景设置。首次准备可能下载数百 MB；无缓存的首次断网不承诺可启动，校验已有输入和读取已保存结果可以离线完成。

## 工作台 MCP

复用 `modmind_modpack_run_server_scenario`：

1. `operation: "files"` 返回当前项目通过文件选择器授权的 JAR。
2. `operation: "start"`，提交 `fixture: {minecraftVersion, loader, loaderVersion, jars: [{path, sha256}]}`、`acceptEula: true` 和 `steps`，立即获得任务 ID。
3. `operation: "state"`，使用任务 ID 读取状态、阶段、进度、日志摘要和最终结果。`waitSeconds` 最大为 20。取消用 `operation: "cancel"`，返回取消已接收状态后继续查询，直到停止和清理完成。

状态查询和文件查询不执行写入；只读工作台不能启动或取消任务。任务属于创建它的项目，不能跨项目查询或取消。应用关闭及任务所属 Agent 取消会停止任务；普通调用超时不等于场景已结束。完成结果写入本地，重启后可凭任务 ID 回读，也可恢复最近一次结果；应用异常退出留下的运行中记录只报告中断，不报告通过。

## 证据与边界

结果分开记录命令断言是否通过、输入文件哈希、运行版本、声明的模组与日志中观测到的模组。观测不完整时返回警告，不能把复制的 JAR 清单称作已加载清单。场景支持命令和新日志断言，不直接解析任意 NBT 文件；NBT 不变或部分写入检查应通过游戏命令或模组测试命令检查具体状态，并输出明确断言标记。

Forge 模组观测使用加载器日志中的模组容器创建记录，并要求服务端已经启动完成；这种证据中的版本来自哈希校验后的 JAR 元数据，结果会注明来源。其他加载器缺少可识别日志时保留未确认警告。Java 当前记录的是实际探测的大版本和执行路径。

服务端退出后删除临时运行文件，保留结果 JSON 和有容量上限的日志；最多保留最近 16 次完成记录，30 天失效。未确认进程退出的目录保留并报告清理失败，不自动删除。Loader 启动成功不代表报错 Issue 中的巢穴业务场景已验证。

## 选型

复用现有 `ServerProcess`、托管 Java、`installServerRuntime`、ZIP/TOML/JSON 读取及 MCP 路由。检查了 XMCL 上游 Mod Parser（MIT），它提供元数据读取但不提供任务隔离、长任务轮询和存档生命周期，现有读取能力已够用，因此不增加该依赖。版本比较使用仓库已锁定过的 `semver` 7.8.5（ISC，https://github.com/npm/node-semver），体积小、离线运行；数值 Maven 区间转换后交给库比较，复杂 Maven 联合区间和无法确认的版本不猜测兼容性。

## 验证记录

2026-10-06 使用独立测试目录和真实 Java 17，通过工作台 stdio MCP → 主机桥接 → 隔离任务服务安装并启动 Forge 1.20.1 / 47.4.23。输入为三个本地合成 lowcodefml JAR，其中一个显式依赖另外两个；实际通过新世界检查、storage 数据写入、正常重启和重启后数据断言，回读三个模组的加载日志证据，最终 `cleanup=complete`。第二次使用已安装的同版本运行时缓存；没有启动或修改用户正式实例。

自动化覆盖项目边界、外部文件授权、哈希变化、依赖缺失、内嵌 JAR、固定版本、任务查询与取消、跨项目拒绝、失败保留证据、只读 MCP、应用重启后结果回读及运行时缓存分离。Playwright 检查现有测试页的折叠状态、选择 JAR、重启步骤、查询失败重试、取消、浅色和深色主题及 480 px 窄窗口。

这不是 Issue 中自研巢穴模组的业务验收；原 fixture 和巢穴场景未取得。Fabric / Quilt / NeoForge 尚未做实机启动验收，不能据 Forge 验证结果宣称全部加载器通过。
