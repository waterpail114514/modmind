# Bulk content and resource mirrors

Read this for batches of cards, traits or similar data, not one recipe or language edit.

Validate representative records against the actual consumer before transforming the batch. Preserve unknown fields and uncertain effects instead of inventing semantics; report unresolved records separately. Reuse deterministic validation and incremental migration, with a recoverable baseline for destructive conversions.

Count definitions, parse/load success, implemented behavior, disabled content and observed behavior separately. Finding a key in a function is useful static evidence, not proof that its event fires. A thousand schema assertions do not certify a thousand playable effects.

Where data and resource mirrors must agree, compare normalized IDs and bytes as appropriate and check missing assets. For large resources keep a manifest of included and excluded inputs. If the task modifies a linked project or child project, register that target with modmind_creation_context before editing and attach the resulting artifact afterward. Missing child projects prevent a complete-delivery claim.
