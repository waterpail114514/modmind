## 目前能确认的支持范围

附件《客户端静默分组与供应商切换》描述的是路由管理协议，不是模型目录。它没有列出任何真实模型 ID、型号总数、全量路由映射、价格或工具调用兼容性。

- 支持的切换目标类型：供应商一、供应商二、后台开放的免费供应商。具体账号与分组必须动态读取，示例 ID 不可硬编码。
- 自定义 API、DeepSeek 官方服务不属于这个切换接口的目标。**这不表示付费中转一定不提供 DeepSeek 模型**；品牌与账号类型必须分开判断。
- 付费切换响应的 `model:null` 不会替客户端选模型，仍需读取目标列表并明确应用用户选择。
- 免费响应给出该免费供应商的完整 `models`，也不能代表所有供应商。
- 仓库默认值为 `gpt-5.6-sol`；这只能证明客户端默认配置，不能证明今天仍在某条上游线路可用。
- 仓库 `modelReasoningRegistry.json`、`modelContextRegistry.json` 来自通用公开模型资料，不是 ModMind 的上游支持清单。
- 官网首页可以公开访问，接入信息 `/keys` 重定向到登录页；目前未取得登录后的实时目录。

因此，当前**无法确认上游一共有多少个模型、完整支持哪些型号**。以下 15 个是用来评审文案与界面的候选示例，不是上游全量目录。获得真实目录后，应按真实 model ID 逐个对齐、补齐和删减。

## 设置页行为

保留“ModMind／本机 Codex”来源入口。ModMind 区域先展示当前模型与额度来源，下面默认给出少量推荐候选，再按家族筛选或搜索。选择候选只更新详情，点击“使用此模型”才开始切换；此按钮就是提交，不再出现额外保存按钮。

每个模型只展示一行定位，选中后展开“适合”“不建议”和额度价格。思考强度、Fast 模式、上下文上限收进高级设置，按真实能力显示。普通页面不暴露供应商编号、分组 ID、baseUrl、Key 或节点参数。

推荐区最终只允许出现本账号可用且已验证适配工作台的型号。先选一个日常主力、一个复杂任务候选、一个轻量任务候选；具体是谁，要看真实线路测试与站内价格，不能直接把效果图的三个示例写成生产规则。

同型号有多条线路时优先保留当前可用线路；需要切换时根据上游健康状态、工作台兼容性与公开的计费规则选路。价格差异会改变用户选择，应在提交旁展示；未知时标明未知，不伪造额度倍率，也不采用模型厂商美元报价代替站内计费。

## 附件中真正需要的协议

1. 用有效模型 Key 初始化独立 `routingToken`，在主进程安全持久化成功后才允许跨供应商切换。Key 与 token 不传给前端、不写日志。
2. `GET /api/device/group` 读取当前账号、分组与可选目标；只读获取全量模型目录（还需要上游补充）。
3. 用户提交具体 model ID 后，选择与它匹配的 account/group，串行 `POST /api/device/group`，携带读取时的 `expectedAccount` 和 `expectedGroup`。
4. 安全保存最新 baseUrl、apiKey、group、node；刷新目标模型列表并确认选择的 exact model ID 存在，再应用模型与匹配的能力设置。付费 `model:null` 不代表成功选中了用户目标。
5. 回读本地与服务端状态后显示“已切换”。读取 `/models` 只能验证目录存在；工作台工具调用适配需要另行集成测试，不能冒充已通过真实推理验证。
6. 现有任务不迁移。涉及全账号 Key 的切换应等受影响的任务完成后再执行，而不只是延迟当前页面应用；服务端跨客户端/网页的任务占用保护仍需确认。

超时、502/503 或部分成功：用独立会话请求 `GET /api/device/group?credentials=1` 恢复真实当前凭据，不能宣称仍在旧线路。可能已成功换供应商却未成功换分组，因此不能盲目重发，也不能自动切回另一家。409 先读取最新状态；429 按 `Retry-After` 退避；凭据待确认时复用同一目标与 Key，限制重试次数并进入冷却。余额不足在原位置说明，提供充值与重新选择，不静默切到免费或其他模型。

## 最小上游补充项

需要**不修改账号状态、无需先切路由**的模型目录。可以扩展现有 GET，也可以新增只读接口；以下字段是建议，不是附件已存在的协议。

- 全部当前账号有权使用的 `modelId/displayName/family`，目录时间与版本。
- 每个模型的 `routes[]`：真实 account、group、可用状态、不可用原因。
- 每条路由的协议与能力：Responses/Chat、流式输出、工具调用、图片输入、推理档位、上下文限制。模型品牌不能代替路由级兼容性。
- 站内价格：输入、输出、缓存计费与单位，或可信的额度消耗说明；不是厂商公开价的简单照搬。
- 推荐顺序或路由策略、健康状态、明确的别名/日期快照关系。

不能为了发现模型逐条 POST 切换：这会停用/结算原 Key、影响其他会话，而且受切换限流约束。若上游暂时只有当前线路列表，先交付当前线路的家族选择器；不能把它宣称为全线路自动找模型。

## 复用与交付边界

- 复用 `deviceIntegration.ts` 的设备授权/请求、`index.ts` 中 `fetchAvailableModels`、现有模型偏好保存、`modelFamily.ts` 与能力注册表。家族识别目前较保守，例如 Claude Fable 不在规则内，实施时须扩展并保留未知回退。
- 仓库已使用 models.dev（MIT）与 LiteLLM 元数据。2026-10-02 查看 GitHub：两仓库均未归档，最近推送日期为 2026-10-01。GitHub 对 LiteLLM 的许可证返回 NOASSERTION，新增整体依赖时必须核对所用版本与目录许可，不能笼统说整个项目都是 MIT。
- 建议继续使用现有少量元数据与静态编辑文案，不引入整套模型代理框架。它们提供通用规格，无法知道 ModMind 账号可切的线路、余额及站内价格。这个切换协议较小，复用现有 HTTP 服务并增加状态恢复即可；不需要新运行时或离线大下载。
- 文案随客户端内置，实际体积远低于 256 KiB；在线可用性不能离线保证。首次断网保留当前设置和本地工作，模型切换提示联网。目录缓存需有容量、TTL、按账号隔离及显式重试，旧目录显示过期状态，不作为可用性凭证。
- MCP 实施时复用同一切换服务：扩展模型目录查询、读取当前选择/切换状态；如允许 AI 发起切换，遵循现有全局配置权限及用户明确意图，不允许模型自行提高消费档位。切换是账号范围操作，必须标明影响范围，不伪装成仅当前项目。命名和工具数量待检查现有注册处决定。

本次仅有设计稿，未接入新接口、未完成 MCP 交付，也未验证任何候选型号的真实线路表现。交互稿通过 JavaScript 语法检查且不含网络请求；已查看浅色桌面、深色桌面、窄窗口静态图并修正字体缺字。浏览器预览受到环境权限校验阻断，不能声称完成点击、深色及窄窗口的浏览器验收。静态效果图由设计代码绘制，不是已上线软件截图。
