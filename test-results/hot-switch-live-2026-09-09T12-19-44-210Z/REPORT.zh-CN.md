# 第二轮：运行中线路切换失败现场

采集：2026-09-09 北京时间 20:19:44–20:25:20。testmod，开发版 PID 30684。总计 670 条事件、36 个 HTTP 请求、2 次深链同步。采集结束，业务代码未修改。

## 本轮结论

实际请求证明：地址和 Key 更新了，但运行时模型没有跟随当前偏好；跨线路继续发送的会话历史也没有满足免费渠道的消息 ID 约束。任务没有完成用户期望的自动续跑。

以下均为客户端请求及应用错误事件证据，不等价于已经获知网站内部渠道实现。

## 已记录的问题

### HS-01 切换后任务停止，必须手动继续

用户确认每次都需要手动点击“继续”。日志对应 ai:resumeRecovery 的调用及后续再次启动事件。目标行为应是同步后自动中断或收尾旧执行、保留任务状态并启动新配置续跑，而不是等待用户手动恢复。此项为修复的最高优先级之一。

### HS-02 运行时模型与当前设置脱节

当前模型偏好先为 Terra，切免费后为 Qwen；请求体始终沿用 Astra。检查期间托管 config.toml 也已经是 Terra。这排除了“只是设置没有写入文件”的解释，但模型固定在原生会话、启动参数还是其他运行时缓存，尚需后续定位。

模型、地址和凭证必须作为同一个执行配置处理。当前请求出现了新地址和新 Key 配上旧模型的组合。

证据：events.jsonl 的 fetch-request 事件 77、108、472、636、662；以及全部 persisted-state 事件。请求详情见 analysis.json。

### HS-03 同步成功后仍向旧地址发请求

供应商一 connected 的时间为 20:22:44.007，20:22:45.478 的 fetch-25 仍向供应商二使用旧 Key 请求，返回 401。后续界面提示“凭证无效，请重新连接”，但本地新凭证已存在。

免费同步时也出现旧请求的 401 在新连接完成后才展示：20:24:06.920 connected，20:24:08.342 事件 608 才输出凭证无效。旧请求失败不能简单等同于当前新凭证失效；本轮随后的新 Key usage 为 ACTIVE。

### HS-04 免费渠道拒绝跨线路历史消息 ID

免费线路的直接错误是：

```text
Invalid 'id': message id must be a string starting with 'msg_',
got 'item_b8c7bbeb897f63dfbf6e9c41'.
```

第一次失败请求 fetch-69：20:24:15.884，HTTP 400；应用终态错误为事件 641，服务 request_id 为 ff1bc292-2b42-47bf-b4cc-55bdccbe991e。

第二次失败请求 fetch-71：20:24:33.949，HTTP 400；应用终态错误为事件 667，服务 request_id 为 b9994129-b30b-408e-84cd-67fd8f3fd79c。

请求体实测包含该 item_ 前缀的 type=message 历史条目。它在供应商一的 fetch-29 历史中已经存在，之后被携带到免费线路；并非免费线路临时生成的错误文字。

免费线路确实拒绝了请求，但本轮不能仅因 Astra 不在它的模型列表中就认定 400 是模型名造成的，错误明确指向消息 ID。也不能用简单全局替换 ID 作为已验证修复，后续需要检查不同条目类型及工具引用的一致性。

### HS-05 不可用配置反复重试

供应商一模型列表不包含 Astra，包含 Terra，但实际连续发出 15 次 Astra 请求并得到 503。没有服务端完整错误体或渠道记录，尚不能精确断言这些 503 的内部原因；可以确认重试期间未修正本地已知的模型配置不一致。

## 警告不是本次免费失败的直接解释

`Model metadata ... not found` 是原生运行时缺少模型元数据的警告。最初供应商二请求仍为 HTTP 200，免费渠道失败则有明确的 HTTP 400 和消息 ID 错误。需要分别解决模型配置、元数据支持和跨线路协议兼容，不能通过隐藏警告代替修复。
